Promote candidate
Promotion edits config.yaml itself (timestamped backup, hot-reload): the candidate starts serving at the weight below, inside the incumbent’s priority tier. The incumbent is never demoted or removed — promote again at a higher weight to shift more traffic.
Promotion backups
Every apply — promote or rollback — writes a timestamped config.yaml backup next to the file. Rolling back restores one through the same discipline: the live file is backed up first (the rollback’s own undo point), then hot-reloaded and audited — so a rollback is itself one rollback away from undone.
